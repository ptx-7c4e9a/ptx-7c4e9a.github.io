# Транспортные системы — демонстрационный прототип

ЕКТП, два варианта КЛК и самостоятельные обоснования решений. Приложение находится в prototype-app. Демонстрационные данные и действия не подтверждают подключение рабочего backend или реальные телематические показания.

## Локальный запуск

Node22+ и pnpm11.25.0. Из prototype-app: pnpm install --frozen-lockfile, затем pnpm dev. Локальный адрес http://localhost:4173/.

Для ЯндексКарт создать локальный.env.local по.env.example; значения не добавлять в Git. Подписывающий секрет не используется в клиентском приложении.

## Сборка

pnpm build:candidate создаёт dist с27прямыми маршрутами и manifest в.local/release-candidate. Для согласованного корневого домена https://ptx-7c4e9a.github.io/ используется base /.

## Проверки

pnpm test и pnpm build. Первый показ проходит сокращённый обзор всех разделов; полная продуктовая приёмка и productionbackend вне этого демо.

## Состав репозитория

В Git входят исходники, публичные ресурсы, настройки сборки, тесты, три эксплуатационных/buildскрипта и единственная fixtureзависимость теста. Локальные ключи, архивы Figma, материалы сбора, QAснимки, node_modules и dist исключены. Исходные тексты лицензий зависимостей/шрифтов находятся вprototype-app/public/licenses.


## Актуальность продуктовых обоснований

Перед каждым релизом сверять снимки и значимые сценарии ЕКТП, КЛК A/B с финальным интерфейсом. Затронутые иллюстрации обновлять через CUA, просматривать в читателе; неизменённые — подтверждать после сверки. `pnpm rationale:check` входит в `pnpm build:candidate`: изменение интерфейса, текстов или снимков останавливает подготовку до новой проверки. Evidence в `prototype-app/source-evidence/rationale-current.json` нельзя обновлять без фактического просмотра. Это проверка актуальности, а не разрешение публикации.
